# Конструктор рецептов 107-1/у

Desktop-приложение для подготовки проекта рецепта по форме 107-1/у. Пользователь заполняет форму в графическом интерфейсе, после чего программа проверяет введённые данные, подставляет их в Word-шаблон и сохраняет сформированный `.docx`-файл на Рабочем столе.

**Версия:** 0.2.1  
**Дата сборки:** 29.08.2026  
**Автор:** © 2026 Жихорев Р.С.

> [!IMPORTANT]
> Приложение является вспомогательным инструментом подготовки проекта рецепта. Оно не осуществляет диагностику, не назначает лечение, не определяет дозы, противопоказания или лекарственные взаимодействия.
>
> Перед подписанием, печатью, выдачей или передачей документа медицинский работник обязан самостоятельно проверить все данные пациента, врача, лекарственного назначения, дозировку, способ применения, количество и соответствие документа действующим нормативным требованиям.

## Возможности

- Графическая форма для ввода рецептурных данных.
- Обновлённый бирюзовый дизайн интерфейса: стилизация формы, полей ввода, кнопки, информационного блока и нижнего колонтитула.
- Использование локального шрифта Kelly Slab в интерфейсе.
- Центрированное окно приложения при запуске.
- Ввод фамилии и инициалов пациента.
- Ввод даты рождения пациента.
- Проверка даты рождения в интерфейсе: поле обязательно для заполнения и должно содержать корректную дату.
- Ввод ФИО врача.
- Ввод лекарственной формы, МНН и дозировки.
- Ввод способа применения препарата.
- Визуальное выделение активного поля ввода при работе с ним.
- Автоматическая подстановка текущих дня, месяца и двух последних цифр года.
- Формирование документа Word `.docx` на основе шаблона.
- Сохранение готового документа на Рабочем столе пользователя.
- Добавление даты и времени формирования в имя файла.
- Уведомление об успешном формировании и сохранении рецепта.
- Отображение версии, даты сборки и информации об авторе в интерфейсе.
- Подготовка к сборке самостоятельного исполняемого файла через PyInstaller.

## Подготовка Word-шаблона

Шаблон должен находиться по пути:

```text
templates/prescription_107-1u_template.docx
```

В соответствующие поля Word-документа необходимо вставить плейсхолдеры `docxtpl`.

```text
{{ d }}
{{ m }}
{{ y }}

{{ patient_fio }}
{{ patient_birthdate }}
{{ doctor_fio }}

{{ drug_1_form_name_dosage }}
{{ drug_1_signa }}
```

### Переменные шаблона

| Переменная | Подставляемое значение |
|---|---|
| `{{ d }}` | Текущий день месяца |
| `{{ m }}` | Текущий номер месяца |
| `{{ y }}` | Последние две цифры текущего года |
| `{{ patient_fio }}` | Фамилия и инициалы пациента |
| `{{ patient_birthdate }}` | Дата рождения пациента |
| `{{ doctor_fio }}` | ФИО врача |
| `{{ drug_1_form_name_dosage }}` | Лекарственная форма, МНН и дозировка |
| `{{ drug_1_signa }}` | Способ применения с автоматически добавляемым префиксом `S:` |

Пример оформления даты в Word-шаблоне:

```text
«{{ d }}» {{ m }} 20{{ y }} г.
```

> [!WARNING]
> Каждый плейсхолдер должен быть расположен в Word как единый текстовый фрагмент. Не меняйте форматирование внутри выражения `{{ ... }}`: Word может разбить его на несколько фрагментов, из-за чего `docxtpl` не сможет выполнить замену.

## Запуск

В активированном виртуальном окружении выполните:

```bash
python main.py
```

Или укажите интерпретатор виртуального окружения явно:

```bat
.venv\Scripts\python.exe main.py
```

После запуска откроется центрированное окно «Конструктор рецептов 107-1/у».

## Работа с приложением

1. Введите фамилию и инициалы пациента.
2. Укажите дату рождения пациента в корректном формате, поддерживаемом полем даты.
3. Введите ФИО врача.
4. Укажите лекарственную форму, МНН и дозировку.
5. Заполните способ применения.
6. Нажмите кнопку «Сформировать рецепт».
7. При ошибке заполнения исправьте поле, отмеченное браузером или интерфейсом формы.
8. Дождитесь сообщения об успешном формировании рецепта.
9. Откройте созданный `.docx`-файл на Рабочем столе.
10. До подписания или выдачи обязательно проверьте содержание сформированного документа.

## Проверка данных и уведомления

Перед отправкой данных приложение использует встроенную проверку HTML-формы.

- Обязательные поля должны быть заполнены.
- Поле даты рождения должно содержать корректное значение даты.
- Если проверка не пройдена, формирование документа не запускается.
- После успешного сохранения документа приложение показывает уведомление с подтверждением результата.

Проверка в интерфейсе предназначена для снижения числа очевидных ошибок ввода. Она не заменяет профессиональную проверку корректности данных пациента, врача и назначения.

## Формирование документа

После успешной проверки формы JavaScript передаёт данные в метод Python:

```python
window.pywebview.api.create_prescription(prescriptionData)
```

Приложение:

1. Получает и очищает введённые значения.
2. Определяет текущую дату и время.
3. Открывает Word-шаблон.
4. Подставляет данные в плейсхолдеры.
5. Сохраняет результат в формате `.docx` на Рабочий стол.
6. Возвращает результат в интерфейс для отображения уведомления об успешном сохранении либо ошибки.

Имя выходного файла формируется по шаблону:

```text
{ФИО пациента} {дата} {время}.docx
```

Пример:

```text
Иванов И.И. 2026-08-23 17-40-15.docx
```

Время записывается в формате `%H-%M-%S`, поскольку символ `:` недопустим в именах файлов Windows.

> [!NOTE]
> Имя файла содержит персональные данные пациента. Для использования в реальной информационной среде рекомендуется рассмотреть переход на внутренний идентификатор пациента или иной вариант, согласованный с локальными правилами обработки персональных данных.

## Сборка EXE

Для создания самостоятельного исполняемого файла можно использовать PyInstaller.

Пример команды:

```bat
pyinstaller --noconfirm --onefile --windowed ^
  --add-data "templates;templates" ^
  --add-data "ui;ui" ^
  --add-data "fonts;fonts" ^
  main.py
```

После сборки исполняемый файл будет создан в папке:

```text
dist/
```

> [!WARNING]
> Папка `fonts` должна быть включена в сборку, иначе файл `KellySlab-Regular.ttf` не будет доступен приложению после упаковки в `.exe`.
>
> Перед распространением `.exe` необходимо проверить работу программы на чистой Windows-системе: запуск и центрирование окна, загрузку CSS и локального шрифта, отображение формы, проверку даты рождения, доступ к шаблону, формирование документа, уведомление об успехе и сохранение на Рабочий стол.

## Типичные ошибки

### Не найден шаблон Word

Если появляется ошибка, связанная с отсутствием файла шаблона, проверьте наличие файла:

```text
templates/prescription_107-1u_template.docx
```

Убедитесь, что:

- имя файла совпадает с указанным в `main.py`;
- файл имеет расширение `.docx`;
- документ не является старым файлом `.doc`, которому вручную изменили расширение;
- при сборке в `.exe` папка `templates` включена в пакет.

### Некорректная дата рождения

Если форма не отправляется, проверьте поле даты рождения:

- поле не должно быть пустым;
- выберите дату средствами элемента ввода или введите дату в формате, который принимает используемый браузерный компонент;
- убедитесь, что дата действительно существует.

### Приложение не запускается

Проверьте:

```bash
python --version
pip show pywebview
pip show docxtpl
```

При необходимости переустановите зависимости:

```bash
pip install --upgrade -r requirements.txt
```

### Не применились стили или шрифт

Проверьте следующее:

- `ui/form.css` подключён в `ui/form.html`;
- в CSS указан корректный относительный путь к `../fonts/KellySlab-Regular.ttf`;
- имя файла шрифта и регистр символов совпадают;
- при сборке в `.exe` в команду добавлен параметр `--add-data "fonts;fonts"`;
- папка `ui` также включена в сборку через `--add-data "ui;ui"`.

### Документ не появился на Рабочем столе

В текущей версии путь определяется так:

```python
Path.home() / 'Desktop'
```

Если Рабочий стол перенесён в OneDrive или имеет нестандартное расположение, путь может не соответствовать фактической папке. В этом случае следует доработать настройку каталога сохранения либо добавить выбор папки пользователем.

### Плейсхолдеры остались в документе

Вероятная причина — Word разбил выражение вида `{{ patient_fio }}` на несколько текстовых фрагментов из-за форматирования.

Удалите плейсхолдер в шаблоне, вставьте его заново целиком и не изменяйте оформление отдельных символов внутри выражения.
