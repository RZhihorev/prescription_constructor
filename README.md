# Конструктор рецептов 107-1/у

Desktop-приложение для подготовки проекта рецепта по форме № 107-1/у. Пользователь заполняет форму в графическом интерфейсе, при необходимости добавляет до трёх лекарственных препаратов, выбирает размер печатного бланка, после чего программа подставляет данные в Word-шаблон и сохраняет сформированный `.docx`-файл на Рабочем столе.

**Версия:** 0.3.1  
**Дата сборки:** 20.09.2026  
**Автор:** © 2026 Жихорев Р.С.

> [!IMPORTANT]
> Приложение является вспомогательным инструментом подготовки проекта рецепта. Оно не осуществляет диагностику, не назначает лечение, не определяет дозы, противопоказания или лекарственные взаимодействия.
>
> Перед подписанием, печатью, выдачей или передачей документа медицинский работник обязан самостоятельно проверить данные пациента и врача, лекарственные назначения, дозировки, способы применения, количество препаратов и соответствие рецепта действующим нормативным требованиям.

## Возможности

- Графическая форма для ввода данных рецепта по форме № 107-1/у.
- Ввод фамилии и инициалов пациента, даты рождения пациента и ФИО врача.
- Проверка даты рождения: поле обязательно, дата вводится в формате `ДД.ММ.ГГГГ`, должна существовать и не может находиться в будущем.
- Ввод первого лекарственного препарата: лекарственная форма, МНН, дозировка и способ применения.
- Добавление второго и третьего лекарственных препаратов как необязательных назначений.
- Поддержка до трёх лекарственных препаратов в одном формируемом документе.
- Автоматическое добавление префикса `S:` к способу применения каждого заполненного препарата.
- Выбор размера печатного рецепта: `A6` (рекомендуемый вариант) или `A4`.
- Использование отдельных Word-шаблонов для форматов `A6` и `A4`.
- Информационное окно по кнопке `i` рядом с заголовком: краткая справка об ограничениях формы № 107-1/у.
- Автоматическая подстановка текущих дня, месяца и двух последних цифр года.
- Формирование Word-документа `.docx` на основе шаблона.
- Сохранение результата на Рабочем столе пользователя.
- Добавление даты и времени формирования в имя файла.
- Уведомление об успешном формировании с напоминанием о двусторонней печати.
- Центрированное окно приложения при запуске.
- Бирюзовый дизайн интерфейса и локальный шрифт Kelly Slab.
- Отображение версии, даты сборки и сведений об авторе в нижней части окна.
- Подготовка к сборке самостоятельного исполняемого файла через PyInstaller.

## Справка по форме

Информационное окно не заменяет нормативную проверку. Оно напоминает, что:

- форма № 107-1/у применяется для препаратов, не требующих специальных бланков № 107/у-НП и № 148-1/у-88;
- на бланке допускается до трёх лекарственных препаратов в случаях, разрешённых правилами оформления;
- для препаратов, не подлежащих ПКУ и относящихся к группам АТХ `N05A`, `N05B`, `N05C` или `N06A`, допускается только одно наименование на бланке;
- обычный срок действия рецепта составляет 60 дней, а при длительном курсовом лечении может быть установлен до одного года;
- форма № 107-1/у не является льготным рецептом; для бесплатного или льготного отпуска используется дополнительное оформление по форме № 148-1/у-04(л) в предусмотренных случаях;
- бланк является российской национальной формой, а приём рецепта за пределами РФ не гарантирован.

> [!WARNING]
> Справочная информация в приложении не исчерпывает правила назначения и оформления. Перед формированием и печатью рецепта необходимо проверить применимость формы, статус ПКУ, предельное количество препарата, срок действия и актуальную редакцию нормативных документов.

## Word-шаблоны

Приложение использует два шаблона:

```text
templates/prescription_107-1u_template_a6.docx
templates/prescription_107-1u_template_a4.docx
```

Формат выбирается пользователем в интерфейсе до формирования документа. Значение `A6` отмечено как рекомендуемое. Выбранному формату должен соответствовать шаблон с корректной разметкой рецептурного бланка.

### Плейсхолдеры docxtpl

В шаблонах должны быть размещены следующие переменные:

```text
{{ d }}
{{ m }}
{{ y }}

{{ patient_fio }}
{{ patient_birthdate }}
{{ doctor_fio }}

{{ drug_1_form_name_dosage }}
{{ drug_1_signa }}

{{ drug_2_form_name_dosage }}
{{ drug_2_signa }}

{{ drug_3_form_name_dosage }}
{{ drug_3_signa }}
```

### Переменные шаблона

| Переменная | Подставляемое значение |
|---|---|
| `{{ d }}` | Текущий день месяца |
| `{{ m }}` | Текущий номер месяца |
| `{{ y }}` | Последние две цифры текущего года |
| `{{ patient_fio }}` | Фамилия и инициалы пациента |
| `{{ patient_birthdate }}` | Дата рождения пациента |
| `{{ doctor_fio }}` | ФИО врача |
| `{{ drug_1_form_name_dosage }}` | Лекарственная форма, МНН и дозировка первого препарата |
| `{{ drug_1_signa }}` | Способ применения первого препарата с префиксом `S:` |
| `{{ drug_2_form_name_dosage }}` | Данные второго препарата; остаётся пустым, если препарат не добавлен |
| `{{ drug_2_signa }}` | Способ применения второго препарата с префиксом `S:`; остаётся пустым, если не заполнен |
| `{{ drug_3_form_name_dosage }}` | Данные третьего препарата; остаётся пустым, если препарат не добавлен |
| `{{ drug_3_signa }}` | Способ применения третьего препарата с префиксом `S:`; остаётся пустым, если не заполнен |

Пример оформления даты в Word-шаблоне:

```text
«{{ d }}» {{ m }} 20{{ y }} г.
```

> [!WARNING]
> Каждый плейсхолдер должен быть единым текстовым фрагментом. Не меняйте форматирование внутри `{{ ... }}`: Word может разделить выражение на несколько фрагментов, и `docxtpl` не сможет корректно заменить переменную.


## Работа с программой

1. Введите фамилию и инициалы пациента.
2. Укажите дату рождения в формате `ДД.ММ.ГГГГ`.
3. Введите ФИО врача.
4. Заполните лекарственную форму, МНН, дозировку и способ применения первого препарата.
5. При необходимости заполните данные второго и/или третьего препарата.
6. Выберите размер печатного рецепта: `A6` или `A4`.
7. При необходимости нажмите кнопку `i` рядом с заголовком, чтобы открыть справку об ограничениях формы.
8. Нажмите «Сформировать рецепт».
9. При сообщении об ошибке исправьте отмеченное или указанное поле.
10. После успешного сохранения откройте созданный `.docx` на Рабочем столе.
11. Проверьте документ перед подписанием, печатью, выдачей или передачей. При печати используйте двусторонний режим.

## Проверка данных

Перед передачей данных в Python приложение проверяет дату рождения пациента.

- Поле не может быть пустым.
- Значение должно соответствовать формату `ДД.ММ.ГГГГ`.
- Дата должна существовать в календаре.
- Дата рождения не может быть позже текущей даты.

Остальные обязательные поля контролируются средствами HTML-формы. Второй и третий препараты являются необязательными. Проверка интерфейса снижает риск очевидных ошибок ввода, но не заменяет профессиональную проверку назначения и документа.

## Формирование документа

После успешной проверки JavaScript передаёт данные в Python API:

```python
window.pywebview.api.create_prescription(prescriptionData)
```

Приложение:

1. Получает и очищает введённые значения.
2. Определяет текущую дату и время.
3. Получает выбранный формат бумаги `A6` или `A4`.
4. Открывает соответствующий Word-шаблон.
5. Подставляет данные пациента, врача и до трёх препаратов в плейсхолдеры.
6. Сохраняет результат в формате `.docx` на Рабочий стол.
7. Возвращает результат в интерфейс для показа уведомления.

Имя выходного файла формируется по шаблону:

```text
{ФИО пациента} {дата} {время}.docx
```

Пример:

```text
Иванов И.И. 2026-09-20 08-30-15.docx
```

Время записывается в формате `%H-%M-%S`, так как символ `:` недопустим в именах файлов Windows.

> [!NOTE]
> Имя файла содержит персональные данные пациента. Для использования в реальной информационной среде рекомендуется рассмотреть переход на внутренний идентификатор пациента или другой вариант, согласованный с локальными правилами обработки персональных данных.

## Ограничения текущей версии

- Поддерживается до трёх лекарственных препаратов, но приложение не определяет нормативно допустимое количество назначений в конкретной клинической и рецептурной ситуации.
- Информационное окно носит справочный характер и не выполняет автоматическую проверку категории препарата, АТХ-кода, статуса ПКУ, дозы или применимости бланка.
- Проверка даты рождения контролирует формат и календарную корректность, но не подтверждает принадлежность даты конкретному пациенту.
- Не реализованы автоматические проверки доз, противопоказаний, лекарственных взаимодействий и клинической обоснованности назначения.
- Не реализованы хранение рецептов, пациентов и история операций.
- Не реализованы аутентификация и разграничение прав пользователей.
- Путь сохранения фиксирован на Рабочем столе текущего пользователя.
- При использовании OneDrive путь к Рабочему столу может отличаться от стандартного.
- В имени сформированного файла используются персональные данные пациента.
- Для каждого формата бумаги необходим корректный и доступный Word-шаблон.

## Типичные ошибки

### Не найден Word-шаблон

Проверьте наличие обоих файлов:

```text
templates/prescription_107-1u_template_a6.docx
templates/prescription_107-1u_template_a4.docx
```

Убедитесь, что:

- имя выбранного шаблона совпадает с путём, указанным в `main.py`;
- файл имеет расширение `.docx`;
- файл не является старым `.doc`, которому вручную изменили расширение;
- при сборке в `.exe` папка `templates` включена параметром `--add-data`.

### Некорректная дата рождения

Если форма не отправляется:

- убедитесь, что поле заполнено;
- используйте формат `ДД.ММ.ГГГГ`, например `07.03.1985`;
- убедитесь, что указанная дата существует;
- не указывайте дату в будущем.

### Документ не появился на Рабочем столе

В текущей версии путь определяется так:

```python
Path.home() / 'Desktop'
```

Если Рабочий стол перенесён в OneDrive или имеет нестандартное расположение, путь может не соответствовать фактической папке. В этом случае требуется доработать выбор каталога либо добавить настройку пути сохранения.

### Плейсхолдеры остались в документе

Вероятная причина — Word разделил выражение вида `{{ patient_fio }}` на несколько текстовых фрагментов из-за форматирования.

Удалите плейсхолдер в шаблоне, вставьте его заново целиком и не изменяйте оформление отдельных символов внутри выражения.

### Не применились стили или шрифт

Проверьте следующее:

- `ui/form.css` подключён в `ui/form.html`;
- в CSS указан корректный относительный путь к `../fonts/KellySlab-Regular.ttf`;
- имя файла и регистр символов совпадают;
- при сборке добавлены папки `fonts` и `ui`.

### Не формируется документ для выбранного формата

Проверьте, что в HTML есть выбранный переключатель `paper-size`, его значение равно `A6` или `A4`, а соответствующий шаблон существует в папке `templates`.
